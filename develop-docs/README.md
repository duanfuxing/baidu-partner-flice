## 当前约定

- 业务代码位于根目录 `src/`，根目录入口为 `main.py`。
- 执行 `python main.py` 默认读取 `input/`；也可以使用 `python main.py --input <目录>` 指定输入目录。
- 依赖统一记录在根目录 `requirements.txt`，项目元数据同步维护在 `pyproject.toml`。
- 流程 1 校验通过后，在每个公司目录写入标准化的 `input.json`，后续流程优先读取该文件。
- 使用 Python + Playwright 控制本机安装的 Chrome。
- 首次无登录状态时暂停，提示人工登录；登录成功后保存 Cookie 和本地存储信息。
- URL 只清理空白字符后进行精确匹配。
- 当前资质入口为新版 `/newaudit#/lice/submit/...`；点击“资质信息审核”卡片内的“查看”并切换新页面，以出现“URL状态概览”为成功标志。旧版入口已废弃。
- 删除经营业务前必须完成输入类型到页面类型的精确映射预检；映射不明确时禁止删除。
- 页面默认缺少输入类型时，通过“经营业务”下拉框精确搜索并添加；不得用近似名称代替。
- 旧版业务整类覆盖逻辑已废弃，仅保留历史记录。
- 新版优先处理“推广审查”，其余输入类型各新增一个业务；每个资质目录对应一张卡片，目录内文件逐张上传，只填写文件和举证链接。
- 新版每张文件上传后调用当前卡片保存方法，等待 `submitlice` HTTP 200 且 `status == 0` 并核验回填，再处理下一张；编号、名称和有效期不填写、不校验。
- 新版最终提交按开关点击“发起审核”并确认，校验页面触发的 `submitall` HTTP 200 且 `status == 0`。
- 主登录 Chrome 和每个 worker Chrome 均在对应阶段结束后自动关闭，失败信息保存在状态 JSON。
- 主进程只执行一次登录流程，关闭登录 Chrome 后自动使用 1 个独立 worker 串行处理公司。
- 调度状态统一写入 `input/scheduler.json`，每家公司同时维护 `execution-status.json`。
- 流程错误默认记录后跳过当前公司，继续处理后续公司；不可恢复的配置错误可以终止任务。
