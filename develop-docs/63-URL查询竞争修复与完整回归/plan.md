# URL 查询竞争修复与完整回归

## 目标
修复任务62正式入口遇到多个 URL 查询立即退出的问题，继续完整实测。用户明确：可以在测试之间修复并重跑，测试运行期间仅观察，不手动补救。

## 证据与设计
- 任务60真实采集出现三个目标 URL 查询，首个 tradeid 与后两个不同，首个 status=1011、后两个成功；任务61也出现两个参数相同的成功查询。页面初始化与查询存在竞争，不能简单接受最新一个响应。
- 仍由页面按钮构造 GET；一次查询出现多个匹配请求时，等待这些请求全部结束且短时间没有变化，丢弃整轮响应，再由程序最多重新点击一次查询。
- 未结束的旧请求不得重查；重查仍有多个请求时停止。401/403保留认证异常。单一明确业务失败不盲目重试。
- 新一轮仅接受新请求对象、完整成功响应与对应表格 URL/URL ID；页面回填期间出现查询竞争同样处理。沿用用户设置的总超时，禁止无限重试。

## 实施与验收
1. 更新 URL 查询等待逻辑和本地 Chrome 夹具：重复查询、初始化错误、乱序响应、在途未结束、持续竞争、回填期间新查询、旧结果拒绝。
2. 运行相关回归。
3. 从 main.py 正式入口执行全部输入，沿用 --no-final-submit；每轮启动前冻结源码，运行期间只读日志和状态，无诊断接管。
4. 失败则记录证据，运行结束后修复相关阻断并重新做完整测试，直至通过或有明确外部阻断。
