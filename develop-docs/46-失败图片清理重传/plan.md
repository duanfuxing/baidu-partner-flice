# 失败图片清理重传

目标：新版逐张上传时检查预览实际HTTP状态和内容；确认失败后删除当前失败项、验证其他成功项完整，再最多重试3次（合计4次）。
范围：新版上传和共用重试的可选校验/清理钩子，旧版保留原保守行为。不触发最终审核，不删除非当前项。
设计：成功上传后立即核对预览HTTP200、SHA256及图片解码；明确结束的5xx、HTTP200但业务status非零、或成功响应后的失败预览进入清理。仅允许已成功列表完整保留且只新增一个可归属当前上传的条目时点该条目删除；删除稳定后重试。未知请求、多个多余项、成功项改变或删除失败均停止。达到上限清除当前坏项后报错。
依赖：现有Playwright及页面已确认的FilePreview删除按钮，无新依赖。
验收：404/200错误内容/5xx残留项可清理重传；3次上限；不动成功项；未知请求与删除失败停止；保存后和最终校验保留。
结果：已实现，完整250项pytest通过（250.57秒），compileall和git diff --check通过。真实登录验收受此前登录状态失效限制；尚未提交和打包发布。

实现：共用上传器增加可选verify_success/cleanup_failed钩子；新版使用已核验预览列表限定当前新增条目，点击FilePreview的.delete-btn，并验证原有文件标识、加载及哈希保持不变。无预览组件的兼容页和旧版保留原保守路径。预览请求只读取页面已出现的地址，记录HTTP码和源文件名，不记录完整地址或认证参数。

## 复查
用户要求复查。重点检查异步回调期间上传请求变化、删除按钮定位是否因列表刷新而漂移，以及页面查询观察器是否可能误判。新增问题先记录再修复，补充针对性回归。

复查确认并修复：删除前重读ID/URL快照，绑定具体DOM按钮；新上传请求集合在成功返回、清理前、删除前和清理后均复查。3个新增失败复现用例修复后通过；相关32项测试通过。此前250项全量结果属于复查修复前，最新相关回归单独记录。

复查验收：新增复现及相关测试32项通过，上传保存/重试兼容14项通过，合计46项针对性回归通过；compileall和git diff --check通过。真实验收仍受登录失效限制，未提交或发布安装包。
