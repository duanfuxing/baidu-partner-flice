# 任务 1：数据格式化与验证开发计划

## 目标

遍历 `input` 目录，将每个公司的目录内容转换为统一的结构化数据，并在任何浏览器操作前完成完整校验。

## 输入结构

```text
input/
└── 公司名/
    ├── url.txt
    ├── input.json                 # 校验通过后生成
    └── 资质类型/
        └── 资质目录/
            ├── 表单信息.txt
            └── 图片或 PDF 文件
```

约定：

- `url.txt` 位于公司目录下，每个公司一个。
- 资质类型目录名直接作为资质类型名称，例如“一类医疗器械”“二类医疗器械”“推广审查”“电商代运营”。
- 每个资质目录必须有一个 `表单信息.txt`。
- 资质文件支持 `.jpg`、`.jpeg`、`.png`、`.pdf`，扩展名大小写不敏感；其他文件忽略。
- 页面允许最多 9 个文件，单个文件不超过 10MB，输入校验应提前拦截超限数据。

## `表单信息.txt` 格式

固定为以下四个标签：

```text
资质编号：...
资质名称：...
有效期至：...
举证链接：...
```

- `有效期至：永久` 表示选择页面的“永久”选项，不填写日期。
- 日期格式为 `YYYY-MM-DD`。
- `举证链接` 可为空；非空时清理首尾空白。
- 解析时按标签识别，不依赖字段顺序，但缺少必填标签或出现重复标签应报错。

## 建议内部模型

```json
{
  "companyName": "公司名称",
  "url": "https://example.com",
  "qualificationTypes": [
    {
      "typeName": "推广审查",
      "qualifications": [
        {
          "indexName": "资质1",
          "qualificationNo": "...",
          "qualificationName": "...",
          "expiry": {
            "permanent": false,
            "date": "2026-11-12"
          },
          "evidenceUrl": null,
          "files": ["/absolute/path/file.jpg"]
        }
      ]
    }
  ]
}
```

内部字段使用清晰、修正后的命名；调用百度接口时严格使用接口真实字段名，例如 `qulificationAuditUrl` 的拼写不能自行修正。

## 开发步骤

1. 定义数据模型和解析异常类型。
2. 遍历公司目录，验证目录名和 `url.txt`。
3. 读取 URL 并移除所有空白字符，将常见的 `http:/`、`https:/` 修正为标准协议；清理后为空则报错。
4. 遍历资质类型和资质目录，忽略非目录项。
5. 解析固定字段，校验编号、名称、有效期和文件列表。
6. 校验日期、永久值、文件扩展名、文件数量和文件大小。
7. 输出结构化数据，并保留源文件绝对路径用于当前进程后续操作。
8. 所有公司校验通过后，在每个公司目录生成 `input.json`；文件中的资质文件路径相对于公司目录保存。
9. 生成可供后续任务消费的结果，不在此任务执行任何网络或浏览器操作。

## 验收标准

- 能正确解析当前 `input` 示例中的全部公司、资质类型和资质目录。
- URL 中的空格、换行和制表符不会进入最终数据。
- 可区分日期有效期和永久有效期。
- 空的举证链接不会导致校验失败。
- 非图片/PDF文件被忽略。
- 缺少 `url.txt`、`表单信息.txt`、必填字段或资质文件时给出明确错误路径。
- 文件超过 9 个或单个超过 10MB 时，在浏览器操作前失败。
- 解析结果不包含 Cookie、Token 等认证信息。
- 校验失败时不生成或更新 `input.json`。
- 校验成功时生成合法 JSON，中文正常显示，文件路径可从 `input.json` 所在目录解析。

## 不在范围内

- 不校验资质图片内容是否与文字信息一致。
- 不调用 OCR。
- 不上传文件。
- 不填写或提交资质表单。
