# 逐文件调用页面保存方法

目标：每个文件上传且身份/预览验证完成后，调用当前资质卡片页面自身的保存方法；确认保存成功后再上传下一文件。
范围：新版逐文件保存，沿用任务52滚动和监听。
设计：只读确认真实组件方法、校验及事件副作用；仅定位当前卡片组件并调用其保存方法，不拼接请求、不修改动态参数；每次保存核对累积文件和举证，再等待页面刷新并重新获取控件。
步骤：源码审计；实现调用与逐文件保存；HTML/Chrome夹具回归。
依赖：当前页面真实组件方法和现有Playwright。
验收：每上传1个文件调用1次保存；文件集合依次增长；保存失败不得开始下个文件；定位不明停止。
不在范围内：最终送审、打包发布、直接构造HTTP保存请求。

源码/页面核对：2026-09-11读取当前静态源码，LiceAdd组件defineExpose包含handleSubmit、isValid、formatFormData、formData、liceId；handleSubmit负责校验、脏检查、动态参数与保存回调。真实生产页面DOM无__vueParentComponent，应用根保留_vnode；已从组件树定位唯一包含目标.form-card的drag-upload-wrapper，并在拦截submitlice/submitall的同一专用浏览器中成功调用空卡片方法。未上传线上文件或最终送审。

调试约定：复用专用浏览器会话处理后续检查，避免每个诊断都启动/关闭；正式worker生命周期保持不变。

完成：每文件核验后主动调用一次当前卡片handleSubmit，验证累积文件、举证和HTTP/业务状态，再等待保存刷新。16项相关场景均已通过（组合15通过、1项旧夹具失败修正后单独通过；组件重建额外复测通过）。未进行真实文件上传/完整Windows业务验收，未提交或打包。
