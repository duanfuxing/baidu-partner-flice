# 任务43：上传文件身份核验与重复修复

## 目标与范围
解决输入三个不同文件却显示重复广告样件，数量核验无法发现的缺陷。依赖任务41/42，沿用现有依赖。

## 设计及步骤
1. 只读审计真实前端上传、回填和保存逻辑，识别身份错配原因。
2. 以文件哈希关联当前资质卡的上传响应文件ID，验证逐次回填和保存集合；不使用全局上传标记跳过合法复用文件。
3. 修复确定的时序/数据问题，禁止凭数量接受重复图片。结果不确定时停止且不重传。
4. 本地HTML无头Chrome覆盖数量相同但内容/ID重复、延迟回调、保存刷新及正常多图。
5. 当前公司真实macOS填写验收，最终送审关闭。

## 验收标准
三个原始文件分别对应三个正确的上传与保存凭据；页面不能用重复图片凑齐数量；相关测试通过，真实验收记录局限。

## 不在范围内
发布、修改输入、全局去重、直接拼接保存或送审参数、自动最终送审。

## 状态
目标卡片已修复并通过重新打开后的持久化核验；源码保护已实现。

## 实现

从真实前端源码确认：savelicepic 返回文件名；上传组件通过 uploaded 事件写入 formData.filename；submitlice 的 upload_file 字段保存该列表；FilePreview 的图片 URL 中 filename 参数对应服务端文件标识。

新增 UploadReceipt 记录本地 SHA-256 与服务端文件名。逐次核对预览标识和顺序，持续稳定1.1秒且图片已解码后才允许下一张；进入卡片取消可能尚未执行的自动保存。保存响应必须对应当前文件列表，并核对其举证链接。保存后及最终集合逐张读取页面已有预览 URL 的内容，校验 SHA-256；失败停止，不盲目重传。使用浏览器上下文中的读取请求，保留登录态且不输出 URL 或动态参数。
