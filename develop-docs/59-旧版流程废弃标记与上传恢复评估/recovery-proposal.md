# 新版资质上传与保存恢复建议（尚未实现）

## 现有能力与限制

- `src/upload_retry.py` 已监听上传请求、响应、结束和失败事件；安全清理后最多重试 3 次，缺失回填仅允许一次额外补传。重试循环尚无显式指数退避。
- `src/new_audit_qualification.py` 已逐文件核验预览内容及文件身份，并主动调用页面卡片保存方法。当前实现不只是模拟点击或等待失焦。
- 保存超时或回填持续不匹配时停止当前公司，尚无完整的远端状态核对和逐文件持久化恢复流程。成功上传凭据主要保存在本次运行内存中。
- 同一操作超时配置被用于上传、保存和回填等不同阶段；顺序等待意味着总耗时可能超过单个配置值。
- 本次没有真实失败日志或网络现场证据，不能确认根因一定是网络或百度服务器。

## 建议的处理顺序

1. 把文件状态分为待上传、上传中、已上传待保存、保存中、已保存待核验、已确认、结果未知。确认保存后再处理下一文件，保持单公司串行。
2. 分别配置上传、保存、预览和页面回填的等待预算，设置单文件总时限。请求仍在进行时只等待，不再次上传或保存。
3. 超时进入结果未知状态。先等待迟到响应，再通过经过验证的只读详情请求或重新打开已保存详情核对远端文件集合和举证链接；刷新前必须保护未保存数据，避免触发额外保存。
4. 远端已存在且内容正确则确认成功；文件已上传但资质保存失败时仅恢复保存。只有确认目标文件未关联、原请求状态足够明确且重试不会重复创建时才补传。仍无法确认则暂停恢复并保留检查点。
5. 预览暂时不可访问时，先有限重试只读预览获取；区分临时访问失败与已取得内容但哈希不一致。避免将一次预览网络失败直接等同于源文件损坏。
6. 对允许重试的操作增加退避，例如 2、4、8、16 秒并加小幅随机延迟，设置次数和总时限。401/403、类型或表单校验错误分类处理；429/5xx 也不能跳过写入结果核对直接重放。
7. 将输入指纹、业务/卡片稳定标识、目录位置、文件哈希、服务端文件 ID、举证链接及最后确认阶段原子持久化。再次运行先与远端核对，仅恢复未完成部分；本地记录不能单独证明远端已保存。
8. 按阶段记录脱敏耗时、状态码、重试原因与恢复结果，区分上传失败、保存失败、预览不可用和回填超时。不得保存 Cookie、Token、完整动态 URL 或请求头。

## 交互方式选择

优先保留浏览器登录和业务选择，以及现有页面保存方法，增强网络监听和恢复。页面内部方法仍依赖百度前端实现，页面升级需回归验证。

如果需要进一步减少 UI 耦合，可以单独评估使用已登录浏览器上下文直接调用上传/草稿保存接口；必须先验证动态标识、字段、重复请求语义及草稿读取能力。改用接口不能消除服务器慢响应或“已处理但响应丢失”的问题。最终 `submitall` 继续通过页面按钮触发，结果未知时不自动重复送审。

## 待验证项

- 新版能否可靠读取服务端已保存的业务、卡片及文件关联。
- 保存同一卡片同一文件集合是否具备可安全重试的语义。
- 草稿稳定标识以及恢复已有业务时的定位方式。
- 弱网、迟到响应、保存成功但响应丢失等本地故障注入测试；随后手工真实填写验收，不自动连接最终送审接口。
