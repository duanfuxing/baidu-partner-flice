# URL查询接口响应监听

目标：按用户最新要求，通过页面点击触发的 geturllist 响应判断 URL 查询结果，不再将全页错误提示认作查询失败。
范围：新版 URL 查询和筛选重置、接口响应校验、表格刷新等待、模拟接口测试。
设计：点击前监听 request/response/requestfinished/requestfailed；仅接受可信域名、精确路径、GET、当前输入 URL 和第一页请求，并关联本轮请求对象，排除上轮在途响应及其他查询。等待请求完成后校验 HTTP 200、JSON 对象及整数 status=0，再等待表格刷新稳定。动态认证参数由页面生成，不构造请求、不记录完整URL或响应原文。慢请求按用户超时设置等待并每10秒记录进度。失败或未知结果停止，不使用旧结果；本次不自动重发查询。
步骤：替换旧的全局错误提示判断；调整页面夹具触发模拟请求；覆盖慢响应、旧响应、无关请求和失败；同步需求并运行相关回归。
依赖：任务45。无新增依赖。用户最新指令覆盖任务45及需求中的“不监听接口”旧约定。
验收：先监听后点击；匹配本次响应成功才允许进入结果行；残留错误提示不影响成功响应；HTTP/业务错误、无效JSON、断网和超时均不得点击旧结果；查询/重置参数保持页面动态生成。
不在范围：上传保存改动、真实业务操作、打包发布。
状态：本地实现及回归完成，未打包发布。

接口依据：从此前本机缓存的百度公开源码 services/xinmin.ts 核对 UrlListResponse：status、data.count、data.list，列表项含url/urlid；据此增加响应结构校验及表格URL/URL ID一致性检查，不臆造字段。HTTP401/403保留AuthenticationRequired语义。
验收：本次相关测试70项通过，补充未授权及新旧详情入口4项通过；compileall、git diff --check通过。包括慢响应、旧响应、无关请求、接口失败、旧表格、空结果及残留提示。未进行真实页面/Windows验收，未使用用户提供的认证参数。
