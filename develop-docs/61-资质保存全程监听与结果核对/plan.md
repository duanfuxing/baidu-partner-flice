# 任务 61：资质保存全程监听与结果核对

## 目标

修复任务 60 已确认的自动保存先完成、局部监听后启动导致保存超时误报；验证真实页面，并评估页面操作的错误处理及接口方案。

## 范围与设计

- 新版上传开始前建立保存监听，覆盖当前资质全部文件的上传与保存，按卡片及本次累积文件/举证匹配自动或主动保存。
- 保存成功已被观察到时直接核对回填；已有相关保存请求进行时等待，不再次触发写入；仅未有相关请求时调用一次页面方法。
- 每卡的每个文件从独立时间边界开始，使用页面组件提供的业务/资质/记录标识及文件集合关联，防止旧响应、其他卡片或较小文件集合误用。
- HTTP/业务失败、网络结果未知和完全未发出请求分开处理；结果未知时尝试只读核对已观察到的当前详情接口，不盲目重传或重放保存。
- 继续保留文件内容与页面回填验证。真实回归使用一个持续复用的项目专用浏览器，优先使用输入中的下一条未上传资质，不删除已保存样本。
- 接口方式评估依据真实请求及源码，区分创建/更新、动态标识、OCR/附加字段和并发自动保存；本轮不把未经验证的接口方式切换为正式默认实现。

## 实施步骤

1. 增加保存生命周期观察模块与明确的状态判断。
2. 接入新版上传/保存，保持旧夹具可验证的单卡调用入口。
3. 本地 Chrome 覆盖提前保存、保存进行中、响应迟到、错卡/旧文件集合、业务失败、读回成功及失败、下一文件停止。
4. 运行相关回归；在专用浏览器完成真实上传及重新打开核验，记录接口评估结论。

## 依赖与范围外

依赖任务 53、55、60；无新增依赖。不涉及旧版恢复、输入覆盖、最终送审、全公司重新执行、打包发布。

## 验收标准

- [x] 自动保存早于主动保存时不再误报超时。
- [x] 进行中的相关写入不重复提交；错卡、旧集合、错误举证和失败响应不能放行。
- [x] 未知结果经只读核对后才可确认，无法确认时停止并说明阶段。
- [x] 本地页面测试及相关回归通过。
- [x] 真实样本经过上传和重新打开核验，或记录具体环境阻断。
- [x] 更可靠的页面判断、错误处理及接口可行性评估已记录。
