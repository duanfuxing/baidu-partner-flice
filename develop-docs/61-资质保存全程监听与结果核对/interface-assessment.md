# 页面操作与接口方式评估

## 结论与证据范围

当前优先使用“页面负责合法参数及提交，网络观察负责成功判断，详情查询负责未知结果核对”的组合。任务 60 已获得真实创建、累积文件更新、OCR、详情刷新和重新打开记录证据；任务 61 验证保存全程观察的实现，并在真实页面完成三文件上传、重新打开及正式只读核对实现验证。纯接口写入尚未完成真实验收，不视为可直接替换的实现。

## 实际依赖

| 阶段 | 已观察接口 / 页面行为 | 判断依据及限制 |
| --- | --- | --- |
| 文件上传 | POST `savelicepic`，multipart `crmid,token,file` | HTTP 200、`status == 0`、返回文件 ID；随后核对当前卡片预览 ID、顺序和源文件内容 SHA-256 |
| OCR | POST `getocrresultbyernielayout` | 样本首图触发，返回的资质名、编号进入保存请求；程序未主动填写这些字段，也不能断言直接提交时可以省略 |
| 单卡创建 | POST `submitlice` | `upload_file` 为累积文件 ID；返回的新记录 ID 与下一次更新的 `lice_index` 相同 |
| 单卡更新 | POST `submitlice` | 后续增加 `lice_index,licemap_id,last_lice_audit_status` 等，`manage_type` 和 `addInfos` 结构也有变化；不能简单重放首个请求 |
| 刷新 / 读回 | GET `geturlinfo`、`geturlandproductinfo` | `data.trade_lice_info.opt[].data[]` 含文件集合、举证及记录身份，适合核对持久化结果；请求 crmid 与内部 crmid 通过同响应 url_info 的 URL 主记录映射 |
| 最终送审 | 页面按钮与确认弹窗触发 `submitall` | 本轮不执行；继续遵守现有规范，不自行拼接动态参数 |

## 更好的页面判断和错误处理

1. 从上传前监听到当前文件的保存、页面回填及内容核验结束；每个文件设置独立观察边界，身份在首次保存生成记录 ID 之前快照。
2. 只接受当前卡片身份、完整累积文件顺序和举证一致的保存成功响应。没有请求、请求进行中、明确失败、结果未知分别报告。
3. 自动保存已完成就复用；仍在进行就等待。需要填写举证或更新文件集合时，在没有相关写入进行的情况下最多主动调用一次当前卡片 `handleSubmit`。
4. 保存请求网络失败且结果未知时，只重用本次已观察到、公司和 URL 上下文匹配的详情 GET，核对唯一记录；请求与详情内部的 `crmid` 不一定相同，只允许通过同一响应的 `url_info` 且 URL 身份一致时建立映射。查询时若出现新的保存，不以旧快照放行。没有可用 GET、身份不全或结果不一致时停止。
5. HTTP 401/403 按认证失效处理；业务失败和无效响应直接保留失败阶段。业务错误码不猜测含义，不把所有非零状态当作可重试网络错误。
6. 上传已有有限重试与失败项清理保护；本次不增加保存写入的盲重试。已发出但未结束的写入不能用一次查询证明其最终结果。

## 方案比较

| 方案 | 可取之处 | 仍需解决的问题 | 当前建议 |
| --- | --- | --- | --- |
| 仅模拟点击与固定等待 | 实现直观，沿用网站行为 | 焦点、鼠标、渲染延迟容易造成误判；等待更久不能弥补错过事件 | 不再单独依赖 |
| 页面提交 + 全程接口判断 + 只读核对 | 使用页面实时参数，处理提前保存和慢响应；可核实持久化 | Vue 组件定位仍受网站更新影响；接口查询也会失败 | 本轮采用 |
| 直接上传与保存接口 | 可减少鼠标和渲染依赖，更易明确超时及记录进度 | 动态鉴权、首次创建/后续更新差异、配置/OCR/附加字段、记录 ID 获取、与页面自动保存冲突、接口变更维护 | 可行性较高，但需要单独验收后才能替代默认流程 |

后续纯接口验证应先分离“上传”和“保存”：复用登录上下文，用实时页面/详情配置取得参数，在隔离的未上传样本中测试创建、追加文件和重新打开核对；明确一种写入主体，不能让页面自动保存与直接 POST 同时修改同卡。超时后的接口方案同样需要只读对账，不会自然获得幂等性。最终送审仍使用页面入口。

## 本轮范围限制

只读核对只有本次观察中出现过匹配详情请求时才可使用；首个保存就断网且从未观察到可重用的详情 GET 时，会明确停止。不会从 DOM 上“有缩略图”推断持久化成功。未测试断网/5xx 的真实百度故障注入，这些分支使用本地 Chrome 模拟接口验证。
