# 最终提交开关与任务选项精简计划

## 目标

精简桌面端任务中心选项，移除业务同学不需要操作的 dry-run 和失败截图开关，新增明确的“完成后执行全部提交”选项，控制所有资质填写并校验完成后是否点击页面最终提交按钮。

## 范围

- 从桌面任务中心移除“仅检查，不修改或提交”。
- 从桌面任务中心移除“失败时保存截图”。
- 新增“完成后执行全部提交”复选框，默认不勾选。
- 未勾选时仍执行经营业务维护、文件上传、表单填写、单项提交和最终集合校验，只跳过 `submitall`。
- 勾选时保持现有行为：点击“本模块提交/全部提交”并校验 `submitall`。
- 在确认弹窗和运行日志中明确显示是否执行最终提交。
- 命令行现有 `--dry-run`、`--screenshots` 参数保留，避免破坏开发和排障能力。

## 设计

- 在 `WorkflowConfig` 增加 `final_submit`，默认值为 `True`，保持命令行和既有调用兼容。
- 桌面端显式传入用户选择，默认 `False`。
- 单项和集合校验通过后：
  - `final_submit=True`：执行最终提交并记录 `final_submission_success=true`。
  - `final_submit=False`：跳过最终按钮，任务按“资质填写完成，未最终提交”返回成功，但不能写入最终提交成功标记。
- 未最终提交的任务不得被调度器当作已锁定送审结果跳过，后续仍可重新运行并最终提交。

## 验收标准

- [x] 任务中心只显示“完成后执行全部提交”一个运行选项。
- [x] 新选项默认不勾选。
- [x] 确认弹窗明确提示是否执行最终提交。
- [x] 未勾选时不调用 `submitall`，但保留完整资质填写流程。
- [x] 勾选时调用一次 `submitall` 并校验成功。
- [x] 运行日志明确记录执行或跳过最终提交。
- [x] 现有测试及新增开关测试全部通过。
- [x] Windows/macOS 打包配置无需业务人员额外配置。

## 完成记录

- `WorkflowConfig.final_submit` 将资质填写完成与最终提交完成拆分。
- 调度状态增加 `finalSubmit`；未最终提交的同一输入可以再次运行，不会被误判为已经送审。
- 桌面端默认不执行最终提交，确认弹窗、运行状态和完成提示均明确展示本次选择。
- 70 项自动化测试通过。
- macOS Intel 冻结包构建、`--self-check` 和实际启动通过。
- Windows x64、macOS Apple Silicon 继续由 GitHub Actions 分平台构建验证。

## 不在范围内

- 删除命令行 dry-run 或截图参数。
- 修改单个资质的提交行为。
- 修改最终提交按钮的页面定位和接口校验规则。
