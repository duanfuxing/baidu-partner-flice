## 实施步骤

1. 修正 `develop-docs/README.md` 中已经过期的任务状态。
2. 只读解析当前输入并运行完整测试。
3. 先执行 CLI `--dry-run`，验证登录、接口、入口和页面版本识别。
4. dry-run 通过后，通过 CLI `--no-final-submit` 或桌面程序关闭最终提交的选项执行真实填写联调。
5. 记录真实页面差异；如需修改代码，先写入 `bugs.md`，修复后增加回归用例。
6. 重新运行完整测试并检查工作区状态。
7. 增加独立 DOM 诊断脚本：复用项目登录状态，只进入新增页并检查业务标题、祖先结构及输入控件，不删除、填写、上传或最终送审；拦截保存/送审请求，不输出页面动态 URL、输入值或认证信息。
8. 若联调失败产生“已保存待送审”但列表为 0 条的测试草稿，只允许对当前东莞样本点击新增页“取消”恢复；不得点击发起审核，也不得删除已送审记录。
9. 按最新确认的输入层级重构新版上传：一个资质目录对应一个卡片，目录内 1–9 个文件批量上传；只有出现下一资质目录时才创建补充资质卡片。
10. 针对真实页面偶发不触发 `submitlice`，审计前端 source map 与运行时 DOM：明确事件绑定位置、触发函数的全部前置条件、去重/防抖状态及文件上传回填时序，再据此调整自动化触发方式。
11. 使用当前源码重新构建 macOS windowed `.app`，双击方式启动桌面 GUI，确认不依赖命令行且最终提交选项默认关闭。
