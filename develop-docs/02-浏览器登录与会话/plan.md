# 任务 2：浏览器登录与会话开发计划

## 目标

使用 Playwright 控制本机安装的 Chrome，支持首次人工登录，并在后续运行中复用已保存的登录状态。

## 方案

- 使用 Playwright Python API。
- 使用本机 Chrome channel，而不是默认下载的 Chromium。
- 以非无头模式运行，方便用户观察页面和人工登录。
- 将登录状态保存为 Cookie 和 localStorage 等 storage state。
- 建议保存路径为 `.auth/storage_state.json`；该文件不得提交到版本库。
- 不自动填写账号、密码、短信验证码或验证码。

## 启动流程

1. 创建或加载 Playwright 浏览器实例。
2. 使用保存的 storage state 创建浏览器上下文；首次运行没有该文件时创建空上下文。
3. 打开 `https://partner.baidu.com/portal/workbench`。
4. 判断是否已进入工作台或出现登录页面/登录跳转。
5. 未登录时，在终端提示用户人工完成登录，并等待登录状态确认。
6. 登录成功后调用 Playwright 的 storage state 导出功能保存 Cookie 和本地存储信息。
7. 将当前上下文交给后续公司搜索和页面操作任务。

## 登录检测

优先使用稳定的页面状态组合判断：

- 当前 URL 是否仍处于登录页面或登录跳转地址；
- 工作台页面是否出现已登录用户区域或工作台特征元素；
- 不以单个易变化的 CSS 类名作为唯一依据。

如果页面无法判断，应暂停并让用户确认，不应盲目调用业务接口。

## 会话失效处理

- 接口返回未授权、页面跳转登录页或工作台特征消失时，标记会话失效。
- 暂停任务并提示人工重新登录。
- 登录完成后覆盖保存新的 storage state，再重试当前可重试步骤。
- Cookie、Token 和 storage state 内容不得写入普通日志、错误信息或截图文件名。

## 验收标准

- 能启动本机 Chrome 并打开工作台。
- 首次无登录状态时能暂停并提示人工登录。
- 人工登录成功后能保存登录状态。
- 关闭程序后再次运行能自动复用登录状态。
- 登录状态失效时不会把登录页误判为业务页面。
- 浏览器关闭、超时和用户取消都有明确错误信息。

## 安全要求

- `.auth/` 不进入版本控制。
- 不在源码中写入账号、密码、Cookie 或 Token。
- 不打印完整请求头和完整 storage state。
- 不复用用户日常 Chrome 的默认个人资料目录，避免干扰用户浏览器和泄露其他站点会话。
