# 经营业务类型映射

## 原则

- 左侧为 `input.json.qualificationTypes[].typeName`。
- 右侧为页面去除 `经营业务N：` 后的完整显示名称或明确别名。
- 删除经营业务只能使用已确认映射。
- “包含文字相似”不能自动视为映射成功。

## 当前映射

| input.json 类型 | 页面经营业务 | 状态 | 说明 |
| --- | --- | --- | --- |
| 推广审查 | 推广审查 | 已确认 | 页面提示为系统自动匹配且不可删除 |
| 一类医疗器械 | 一类医疗器械（不可个人，B） | 已确认 | 页面默认可能不存在；通过“经营业务”下拉框搜索“一类医疗器械”后添加 |
| 二类医疗器械 | 二类医疗器械（不可个人，B） | 已确认 | 可忽略全角/半角括号和多余空白 |
| 三类医疗器械 | 三类医疗器械（不可个人，B） | 可配置 | 当前 input.json 暂无该类型 |
| 电商代运营 | 电商代运营【房产承诺函传营业执照（如未要求提交承诺函请忽略）】 | 可配置 | 使用完整登记别名，不直接模糊匹配 |
| 入驻商城类 | 入驻商城类（不可个人，C2） | 可配置 | 与“一类医疗器械”是不同经营业务，不得互相映射 |

## 页面规范化

允许的纯展示规范化：

- 去除前缀 `经营业务`、序号和冒号。
- 去除首尾空白。
- 连续空白合并为一个。
- 中文/英文括号仅在映射表已经登记时视为等价。

不允许：

- 将“一类医疗器械”映射为“入驻商城类”。
- 将“二类”同时匹配“二类、三类”。
- 根据卡片内资质标题反推经营业务并执行删除。

## 缺失类型的搜索添加

- 页面默认未加载输入所需类型时，在“经营业务”下拉框中使用输入类型名精确搜索。
- 下拉候选项必须通过显式映射规范化后唯一匹配；不能选择仅部分文字相同的候选项。
- 选择候选项后点击“添加”，等待新经营业务面板出现，再重新扫描全部面板。
- 新面板显示名称必须与映射结果一致，否则停止当前公司。
- 已存在的页面类型不得重复添加。

## 开发配置建议

映射使用代码常量或单独 JSON/YAML 配置，但必须：

- 有唯一规范键。
- 支持多个已确认页面别名。
- 标记 `mandatory` 和 `deletable` 预期。
- 启动时检查映射冲突。
- 在运行结果中记录规范类型名，不记录页面动态序号。
