# 保存后列表刷新恢复

## 目标与已知证据
完整实测第二轮：推广审查资质3第二文件已完成上传及submitlice成功校验，但后续列表刷新先出现遮罩，随后当前卡片消失，30秒后失败。不能通过重传已保存文件处理页面刷新故障。

## 设计与步骤
1. 观察页面自身发出的详情 GET，复用原始请求读取；仅网络异常、5xx 和已观察可恢复的 status1009 有限重读一次。
2. 将最终响应交给页面原有渲染逻辑，不重传文件或重放保存。每次保存后仍须核对文件、顺序、举证及保存状态。
3. 认证错误或重读失败明确上报；详情未读取完成时，不把暂时空列表作为新增依据。
4. 本地 Chrome 配合 HTTP 服务覆盖成功、重试和拒绝分支，再从正式入口验证。运行期间只观察。

## 依赖与范围
依赖任务61、63、64；不最终送审，不新增依赖，不打包。不通过全页刷新丢弃未保存业务配置，不人工修补测试结果。

## 状态
实现与本地验证完成；第三轮真实验证读取及续传正常，整体新增业务阻断由任务66继续处理。

## 诊断后的设计调整

独立只读诊断 `logs/qualification-trace-20260912-194555/` 观察到 geturlinfo HTTP200/status1009，编辑页无文件输入；未上传、保存或手动刷新。此前任务60中相同详情读取在重新加载后恢复成功。卡片消失时父组件回调不可取得，因此不采用保留Vue回调的方案，改为在页面原始GET上恢复读取：

- 仅拦截可信百度域名 geturlinfo/geturlandproductinfo 的 GET；复用原页面生成的完整请求，最多重试一次。
- 可重试：网络读取异常、5xx、已观察可恢复的 status1009；其他业务错误和401/403原样交还，不泛化错误码含义。
- 用 route.fetch 获取，再将最终响应 fulfill 给原页面，使页面原有回填回调执行；不自行构造动态参数，不发送上传/保存/最终送审 POST。
- 单次读取超时不超过页面超时的三分之一且最多10秒，给一次重试和页面稳定核验留出预算。
- Playwright route启用会禁用页面HTTP缓存，这是当前实现的明确限制；日志记录脱敏接口路径、重试和状态。
- 等待“无已保存业务”结论时增加正在读取和读取完成后的短暂稳定检查，避免初始化仍在读取时把暂时0条当作最终结果。

第三轮正式实测：成功恢复8个已保存文件并补传推广审查缺失的1个文件，推广审查整类校验通过。详情GET经正式恢复层读取并正常驱动页面渲染。本轮没有遇到1009重试；该分支由本地HTTP服务验证。之后清空默认业务再新增一类医疗器械时卡片判断超时，转任务66处理。源码一致，无人工运行中操作。

最终验收：任务66第五轮全量成功，4类业务11份资质19文件核验通过，未送审。测试全程无人工干预。见 [完整验证](../66-空业务页新增卡片兼容/verification.md)。
