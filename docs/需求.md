# 任务

现在需要设计一个浏览器点击的任务。核心就是去百度营销代理商自助平台，根据input提供的信息，上传“资质”。

# input 目录说明

一级目录为公司名
二级目录为资质类型
    目录内按照资质1、资质2为目录排列，每一个都有文字.txt 为上传资质是提交的表单信息
url.txt 为要选择的URL

根据input目录结构提取整合为结构化数组信息。

```JSON
[
    {
        "comanyName":"武汉市扬晟鸣商贸有限公司",
        "url":"https:/iankang.baidu.com/u/YiCD8dIK?260528heh01",
        "flice":[
            {
                "type":"电商代运营",
                "files":[
                    {
```

# 流程

1、数据格式化与验证：
    - 先根据input目录做数据格式化提取，做参数验证；URL去除空白，并修正常见的协议单斜杠。
    - 所有公司数据验证通过后，在对应公司目录生成 input.json，供后续流程读取。
    - 将数据整理到input字段下

2、登录
    - 打开网址首页：https://partner.baidu.com/portal/workbench
    - 提取cookie

3、搜索公司
    - 调用接口：【公司搜索接口】传递参数custName（一级目录公司名）
    - 搜索结果只能用有一个，多个直接提示报错
    - 在搜索结果中提取参数custId

4、进入资质页面
    - 调用接口：【获取资质链接接口】传递参数custId，提取返回值qulificationAuditUrl字段
    - 新页面打开qulificationAuditUrl
    - 在页面加载完成后，找到（//*[@id="app"]/section/section/main/div/div[2]/div/div[2]/div[3]/div[2]/div[1]/div/div[1]/div[1]）点击。
    - 等待页面重新加载，检查URL域名为fkzhunru.baidu.com、路径为/flice且Hash以#/truth/submit开头，并确认页面出现“URL状态概览”

5、选择URL进入资质提交区域
    - 获取input.url字段
    - 在页面的中再到class属性是url-view的div区域
    - 然后去匹配到input.url字段的内容，找到对应的 操作列的查看按钮并点击
    - 在url-view区域会出现“行业资质”模块为成功加载到资质的表单提交区域

6、资质表单信息提交
    - “行业资质”区域可能存在多个经营业务。读取 input.json 中的资质类型，并通过显式类型映射与页面经营业务匹配。
    - 先处理页面已经存在且输入需要的经营业务。每个类型都以 input.json 做整类覆盖，不跳过页面已有资质。
    - 删除多余经营业务，只保留输入需要处理的业务，以及系统强制保留且不允许删除的业务。
    - 输入需要但页面默认不存在的类型，通过“经营业务”下拉框精确搜索候选项，选择后点击“添加”。
    - 新增经营业务后重新扫描页面，确认类型唯一出现，再上传和提交该类型下的全部资质。
    - “一类医疗器械”应搜索并添加为“一类医疗器械（不可个人，B）”，与“入驻商城类（不可个人，C2）”无映射关系。
    - 删除或添加前必须完成全部类型及下拉候选项预检；映射缺失、匹配歧义或页面重复时停止当前公司，禁止猜测操作。
    - 已有资质中有删除入口的卡片全部删除；每次删除前核对资质编号和名称，删除后重新扫描。
    - 每个类型第一张资质卡不可删除：用 input.json 中该类型第一条资质编辑覆盖；若为空白卡则直接填写。
    - input.json 中其余资质全部通过“上传备用资质文件”重新上传，不因页面内容一致而跳过。
    - 新增经营业务的第一张必填资质可能直接展开为面板内嵌表单；此时直接在卡片内上传、填写和提交，不等待弹窗。
    - 同一经营业务下允许资质编号重复；编号和名称同时重复时无法区分，输入校验阶段直接报错。
    - 按 input.json 中的顺序上传一个或多个资质文件。
    - 文件上传后可能出现 OCR 识别结果或“OCR未识别到数据，请补充资质信息”提示；直接关闭提示。
    - OCR 结果不作为表单数据来源。始终以 input.json 中的资质编号、资质名称、有效期和举证链接为准覆盖填写，并在提交前回读校验。
    - “有效期至：永久”时勾选“永久”，否则填写 YYYY-MM-DD 日期；举证链接非必填。
    - 提交每个资质后，等待弹窗关闭及异步卡片完整渲染；连续核对编号、名称、有效期、举证链接和文件数量一致后，再继续下一项。
    - 单个资质失败时记录并直接输出原始错误，停止当前公司，避免在页面状态未稳定时继续操作后续资质。
    - 所有经营业务和单个资质均处理成功、页面最终集合与 input.json 一致后，根据桌面任务的“完成后执行全部提交”选项决定是否点击页面底部“本模块提交/全部提交”。
    - 启用最终提交时必须校验 `submitall` 返回 HTTP 成功且 `status == 0`；未启用时完成资质填写后直接结束，不调用 `submitall`。任一单项失败时始终禁止最终提交。
    - 主登录 Chrome 和每个公司 worker Chrome 均在对应阶段结束后自动关闭；失败详情写入状态 JSON。

7、多个公司自动调度
    - 主程序先统一解析所有公司数据并生成 input.json。
    - 只执行一次登录检测或人工登录；保存登录状态并关闭该 Chrome 后，再启动公司处理 worker。
    - 不设置 `--workers`：1 个公司启动 1 个独立 Playwright Chrome；2 个及以上公司最大同时启动 2 个。
    - 例如 3 个公司先同时处理 2 个，任意一个完成并关闭 Chrome 后再处理第 3 个。
    - 每个 worker 只加载登录状态，不重复执行登录检测或人工登录流程。
    - `input/scheduler.json` 统一记录排队和正在执行的公司，并使用文件锁防止多个主程序争抢同一公司。
    - 每个公司目录写入 `execution-status.json`，记录 queued、running、success、failed、dry-run-success、PID、时间、结果路径和错误。
    - 相同输入已经完成最终提交时直接跳过，避免最终送审后页面锁定仍被重复处理。
